# QA-nested-submodule-test-23-July

A minimal [Express.js](https://expressjs.com/) HTTP server that exposes two plain-text `GET` endpoints: a preserved root endpoint returning `Hello World` and a `/good-evening` endpoint returning `Good evening`.

## Overview

This project is a small, single-file Express.js web server. It preserves the baseline root endpoint (`GET /`), whose response body is exactly `Hello World`, and adds a second endpoint (`GET /good-evening`), whose response body is exactly `Good evening`. The server is started with `npm start` and listens on a configurable port — `3000` by default, overridable via the `PORT` environment variable. It is intentionally minimal: a two-route text server with no database, authentication, or additional frameworks.

## Prerequisites

- **Node.js `>= 18`** — required by Express 5 (verified on Node.js v22.x).
- **npm** — bundled with Node.js; used to install dependencies and run the `start` script (verified on npm v11.x).

## Installation

Install the project's dependencies from the repository root:

```bash
npm install
```

This installs Express (`^5.2.1`) and generates `package-lock.json`, which pins the exact resolved dependency tree. Installed packages live in `node_modules/`, which is git-ignored and never committed.

## Running the server

Start the server with:

```bash
npm start
```

This runs `node server.js`. By default the server listens on port `3000`. To use a different port, set the `PORT` environment variable:

```bash
PORT=8080 npm start
```

On startup the server logs `Server listening on port <PORT>`.

## Endpoints

| Method | Path | Response body | Content-Type |
| --- | --- | --- | --- |
| `GET` | `/` | `Hello World` | `text/html; charset=utf-8` |
| `GET` | `/good-evening` | `Good evening` | `text/html; charset=utf-8` |

Example requests (with the server running on the default port):

```bash
curl http://localhost:3000/              # -> Hello World
curl http://localhost:3000/good-evening  # -> Good evening
```

Any other path returns Express's default `404 Not Found` response.

## Notes on submodules

Despite the repository's name and nested layout, **no Git submodules are configured**. Both `.gitmodules` files (at the repository root and in `user-service-part/`) are empty and declare no submodule sections, and every tracked entry is an ordinary file. The directories `user-service-part/` and `user.js/`, and the files `user-service` and `user.js/validation-lib`, only *resemble* a nested-submodule layout — they are plain tracked entries.

All directories in the tree are nevertheless documented in full: this root `README.md`, together with `user-service-part/README.md` and `user.js/README.md`, covers every directory, and each JavaScript source file carries a JSDoc header. No directory or file is skipped on the grounds that it belongs to a submodule.
